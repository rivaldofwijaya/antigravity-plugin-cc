# Spec: `agy` 1.1 compatibility and the JSON runtime

**Status:** proposed
**Date:** 2026-08-27
**Author:** assessment of `antigravity-plugin-cc` @ `abe95bb` against `agy 1.1.21`
**Supersedes the contract in:** `docs/antigravity-cli-reference.md` (written against `agy 1.0.3`)

---

## 1. Background

The plugin was built in May 2026 against `agy 1.0.3`. The Antigravity CLI is now
`1.1.21`. Three months of upstream change have (a) broken one runtime behaviour the
plugin depends on, (b) invalidated a claim the plugin repeats in four files, and
(c) added a structured-output mode that makes most of the plugin's log-scraping
layer unnecessary.

Everything asserted below about `agy` was verified live on `1.1.21` / macOS on
2026-08-27, not read from documentation.

### 1.1 What is broken

**B1 — auth-failure detection no longer fires.**
`agy` now wraps every log line with a `ERROR: logging before google.Init: ` prefix
*ahead of* the glog stamp, and the signed-out message text changed to
`You are not logged into Antigravity.`. Neither matches `logscan.mjs`'s severity
test (`/^[EF]\d{4}\s/`) nor its auth keyword list
(`UNAUTHENTICATED|not authenticated|login required|PERMISSION_DENIED`). Verified:

```
scanAgyLog(<real signed-out log>) → { conversationId: null, error: null, errorLines: [] }
```

Consequence: a signed-out run produces empty stdout, `scan.error === null`, and
`antigravity.mjs` writes `status: "done"` and renders "no recognizable error was
found in the log". The plugin's headline feature — *print mode exits 0 on failure,
so we read the log and tell you what really happened* — silently no-ops for the
auth case. Quota detection still works, because `RESOURCE_EXHAUSTED` matches on
keyword alone with no dependence on the line prefix.

**B2 — `stripGlogPrefix` is a no-op.**
Same root cause: the regex anchors at `^[EFIW]\d{4}`. Backend error messages are
now relayed to the user with `ERROR: logging before google.Init: E0827 03:04:06.823240      80 errorreport.go:223] `
still attached, and `dedupe()` — which keys off the stripped message — loses its
ability to collapse the wrapped/bare duplicate pair.

**B3 — conversation files are `.db`, not `.pb`.**
`~/.gemini/antigravity-cli/conversations/<uuid>.db`. `cmdSetup`'s auth heuristic
tests `f.endsWith(".pb")`; that branch is dead and passes today only because
`installation_id` is also checked.

**B4 — the "no `--model` flag" claim is false.**
Asserted in `README.md:70`, `docs/antigravity-cli-reference.md`,
`skills/antigravity-cli-runtime/SKILL.md:44`, and
`skills/gemini-3-prompting/SKILL.md:24`. `args.mjs` goes further: it parses
`--model` specifically in order to warn the user off it and discard it
(`antigravity.mjs:230-236`).

**B5 — hardcoded model naming.**
`Gemini 3.5` appears in ~30 places including the untrusted-output banner in
`render.mjs:22,30` and `renderBackgroundStarted`'s "running with Gemini 3".
`agy models` on 1.1.21 returns `gemini-3.7-flash-{high,medium,low}`,
`gemini-3.6-flash-*`, `gemini-3.5-flash-*`, `gemini-3.1-pro-{high,low}`,
`claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium`.

### 1.2 The new `agy` surface (verified)

Flags added since `1.0.3`: `--model`, `--effort`, `--mode`, `--agent`,
`--output-format`, `--input-format`, `--json-schema`, `--project`,
`--new-project`, `--disable-slash-commands`. Subcommands added: `models`,
`agents`, `mcp`, `update`.

`--output-format json` on success:

```json
{"conversation_id":"a717…","status":"SUCCESS","response":"OK\n","duration_seconds":2.135746,
 "num_turns":1,"usage":{"input_tokens":14549,"output_tokens":1,"thinking_tokens":0,
 "cache_read_tokens":0,"total_tokens":14550}}
```

and on failure — **still exit code 0**:

```json
{"conversation_id":"","status":"ERROR","response":"","error":"invalid model selection …",
 "duration_seconds":0,"num_turns":0,"usage":{…}}
```

There is no `model` field in the JSON. Two upstream fixes matter to us:
`1.1.18` fixed print mode exiting 0 with an empty response on a dropped agent
stream; `1.1.20` fixed print mode treating benign tool errors as fatal exit codes.
Both are failure modes this plugin currently works around.

## 2. Goals

1. Restore correct failure reporting on `agy` ≥ 1.1 (B1, B2).
2. Make the JSON contract the primary runtime path, with the text+log path
   retained as a fallback (improvement A).
3. Expose the capabilities the plugin currently denies exist: `--model`,
   `--effort`, `--mode plan` (improvements B, C).
4. Close the operational gaps: version advisory, job-store growth, empty-result
   ambiguity, fork metadata (improvements D–G).
5. Bring every document and skill back in line with the verified CLI.

### 2.1 Non-goals

- Interactive/TTY use of `agy`. The plugin stays headless.
- `--input-format stream-json`, `--json-schema`, `--agent`, `--project`, MCP
  management. Out of scope; note them in the reference doc as unused surface.
- Changing the untrusted-output fencing design. It works; only its wording changes.
- Auto-updating `agy` on the user's behalf. Advise, never execute.

---

## 3. Global constraints

- **Node.js ≥ 18**, ESM, **zero runtime dependencies**. Unchanged.
- **Stdlib only.** No semver library — write the comparison.
- The companion's stdout is Markdown relayed verbatim to the user. Never print
  diagnostics to stdout; diagnostics go to stderr.
- **Never widen agy's write authority.** `--dangerously-skip-permissions` stays
  required for print mode to act, and stays off nothing by default. No change to
  the default write-capability of `delegate`.
- **Backwards compatibility with `agy` 1.0.x is best-effort, not guaranteed.**
  The plugin must not crash on an old binary; it may report reduced fidelity.
- Every behavioural claim added to a doc must be verifiable by running a command
  the doc names.
- Model names must never be hardcoded in user-facing copy. Say "Antigravity", or
  print the model the run actually used.

### 4.2 The `RunResult` contract (improvement A)

`lib/result.mjs` is the new seam. Everything downstream — foreground render,
background `reconcile`, `cmdResult` — consumes this one shape and nothing else.

```js
/**
 * @typedef {Object} RunResult
 * @property {"success"|"empty"|"failed"} outcome
 * @property {string}  responseText      // "" when none
 * @property {string|null} conversationId
 * @property {{kind:"quota"|"auth"|"backend"|"timeout", message:string, resetsIn:string|null}|null} error
 * @property {{inputTokens:number, outputTokens:number, thinkingTokens:number,
 *             cacheReadTokens:number, totalTokens:number}|null} usage
 * @property {number|null} durationSeconds
 * @property {number|null} numTurns
 * @property {"json"|"log"} source        // which path produced this
 */

export function parseAgyJson(stdout)               // → object|null (null when not JSON)
export function fromJson(json)                     // → RunResult
export function fromLegacy({stdout, logText})      // → RunResult   (wraps scanAgyLog)
export function classifyRun({stdout, logText, timedOut, printTimeout}) // → RunResult
```

**`classifyRun` resolution order — this order is the specification:**

1. `timedOut` → `{outcome:"failed", error:{kind:"timeout", …}, source:"json"}`.
   Timeout wins over everything; a partial JSON blob from a killed process is not
   trustworthy.
2. `parseAgyJson(stdout)` returns non-null **and** the object has a string
   `status` field → `fromJson`.
3. Otherwise → `fromLegacy` (stdout as plain response text, `scanAgyLog` for the
   conversation id and the error).

**`fromJson` mapping:**

| JSON | RunResult |
| --- | --- |
| `status === "SUCCESS"` and `response.trim()` non-empty | `outcome:"success"`, `responseText: response.trim()` |
| `status === "SUCCESS"` and `response.trim()` empty | `outcome:"empty"`, `error: null` |
| `status !== "SUCCESS"` | `outcome:"failed"`, `error: classifyErrorText(json.error ?? json.status)` |
| `conversation_id` empty string | `conversationId: null` (normalise `""` → `null`) |
| `usage` present | camelCase it; missing numeric fields default to `0` |

`parseAgyJson` must tolerate leading/trailing whitespace and log noise on the
same stream: try `JSON.parse(stdout.trim())` first, and if that throws, try the
last line of stdout that starts with `{` and ends with `}`. If both fail, return
`null` — never throw.

**Rationale for keeping the legacy path.** It costs one small module, it is
already written and tested, and it is the only thing that works if a user's `agy`
predates `--output-format`. Deleting it would trade a working fallback for
nothing.

### 4.3 Invocation changes (`lib/agy.mjs`)

`buildPrintArgs(opts)` gains, in this emission order (all flags first, `-p <prompt>`
strictly last — that ordering requirement is unchanged and still load-bearing):

| New option | Emits | Notes |
| --- | --- | --- |
| `opts.jsonOutput` (default **true**) | `--output-format json` | The new default for every print run. |
| `opts.model` | `--model <value>` | Only when the caller passed one. Never defaulted — an unset model means the user's `settings.json` default, which is theirs to choose. |
| `opts.effort` | `--effort <low\|medium\|high>` | Validated by `args.mjs`; an invalid value is a companion-side error, not an `agy` round-trip. |
| `opts.mode` | `--mode <accept-edits\|plan>` | Set to `plan` by `--plan`. |
| `opts.disableSlashCommands` (default **true**) | `--disable-slash-commands` | See §4.4. |

**Flag-rejection fallback.** An `agy` that predates a flag exits non-zero and
writes a flag-parse error to stderr. `runForeground` gains a single automatic
retry: if `code !== 0` and stderr matches
`/flag provided but not defined|not defined: --|unknown flag|invalid flag/i`, strip
`--output-format json` and `--disable-slash-commands` from the args and run once
more. Emit a one-line note to **stderr** (never stdout) recording the downgrade.
Retry at most once; never retry a run that produced any stdout. `--model`,
`--effort` and `--mode` are **not** stripped by the retry — those are explicit user
requests, and an old binary rejecting them must surface as an error the user sees,
not as a silent downgrade to a different model.

`spawnBackground` uses the same args. Background runs cannot retry (the process is
detached and unwatched); a background job whose stdout fails to parse falls
through to `fromLegacy`, which is exactly the correct degradation.

### 4.4 Slash-command expansion (hardening, folded into A)

`agy --help`: `--disable-slash-commands` — *"Disable slash command and skill
expansion in print mode."*

`review` embeds an arbitrary git diff into the prompt, and `delegate` embeds
arbitrary user text. A diff line beginning with `/` — trivially plantable in a
repository under review — is currently eligible for slash-command or skill
expansion inside `agy`. That is a live prompt-injection channel into a
write-capable agent, and it is the same class of issue the AST10 audit closed on
the Claude Code side.

The companion therefore passes `--disable-slash-commands` on **every** print run.
There is no opt-out flag; the companion never needs `agy`-side slash commands.

### 4.5 New user-facing flags (improvements B, C)

Added to `args.mjs`:

- `VALUED_FLAGS` gains `effort`. `model` stays in `VALUED_FLAGS` but is now
  **forwarded**, not warned about and dropped. Delete the `parsed.valued.model`
  warning block at `antigravity.mjs:230-236`.
- `--plan` (boolean) → `--mode plan` **plus** `--sandbox`.
- Validation: `--effort` must be one of `low|medium|high`; anything else prints a
  companion error naming the three valid values and exits without spawning `agy`.
- `--model` is passed through **unvalidated**. `agy`'s own rejection message
  enumerates every available model (verified above), which is a better error than
  any list the plugin could hardcode and would have to maintain.

**Containment matrix after this change** — this table is the source of truth for
the docs and must be reproduced in `skills/gemini-3-prompting/SKILL.md`:

| Flag | `--sandbox` | `--mode plan` | No-write preamble | Use for |
| --- | --- | --- | --- | --- |
| *(default)* | no | no | no | Apply the change; review the diff after. |
| `--sandbox` | yes | no | no | Let it try things, contained from the real tree. |
| `--read-only` | yes | no | yes | Investigation and explanation. |
| `--plan` | yes | yes | no | "Tell me how you'd do it" — `agy`'s own planning mode. |
| `review` | yes | no | yes | Always. Not overridable. |

`--read-only` deliberately does **not** gain `--mode plan`. Plan mode changes what
the agent produces (a plan) rather than what it is permitted to do, and
`--read-only` is used today for "explain how X works", where a plan is the wrong
output. They are different intents and stay separate flags.

**Honesty requirement, unchanged:** none of these is a hard write barrier.
`--dangerously-skip-permissions` must stay on for print mode to act at all. Every
document that mentions containment repeats that, and says to check `git status`.

### 4.6 `logscan.mjs` repair (B1, B2)

1. **New `unwrapLogLine(line)`**, applied before every other test:
   - strip a leading `ERROR: logging before google.Init: ` (repeatably — apply
     while the prefix matches, capped at 4 iterations to bound the loop);
   - then strip the glog stamp `^[EFIW]\d{4}\s[\d:.]+\s+\d+\s+\S+\]\s*`.
   `stripGlogPrefix` becomes a thin wrapper over `unwrapLogLine` and keeps its
   existing exported name and its "no-op on plain text" behaviour.
2. **`extractErrorLines`** unwraps first, then applies the severity test to the
   unwrapped remainder — so `E0827 …` is detected again regardless of wrapper.
3. **Auth patterns** gain `not logged in(to)? Antigravity` and
   `error getting token source`.
4. **Extract `classifyErrorText(text)`** from `classifyError` and export it, so
   `result.mjs` can classify `json.error` with the identical logic. `classifyError(lines)`
   becomes `classifyErrorText(lines.join("\n"))`.

**False-positive hazard — must be tested, not assumed.** The two new auth patterns
appear in the log of *successful* runs; a real signed-in run on 1.1.21 logs
`error getting token source: You are not logged into Antigravity.` during startup
before the keyring resolves. This is safe only because the log is consulted
exclusively when there is no response text. That invariant is currently implicit
in the control flow of `antigravity.mjs:274-296` and `jobs.mjs:97-107`. This spec
makes it **explicit and enforced**: `classifyRun` reaches `fromLegacy`'s error
branch only when `stdout` yields no response text, and a required test
(§5, T-L4) drives the companion end-to-end with a success response whose log
contains those lines and asserts the output is a normal response with no auth
error anywhere in it.

### 4.7 Job store (improvements E, F)

**`empty` status (F).** Add a fourth terminal status alongside `done`, `failed`,
`cancelled`. `reconcile` and the foreground path both derive status directly from
`RunResult.outcome`: `success → done`, `empty → empty`, `failed → failed`.

This also fixes a correctness bug that improvement A would otherwise introduce:
`reconcile` currently reads `if (output) job.status = "done"`. Under
`--output-format json`, a *failed* background run writes a non-empty JSON blob to
`output.txt`, so the existing check would mark every failure as done. `reconcile`
must parse `output.txt` through `classifyRun`, never test it for emptiness.

`renderJobStatus` and `renderStatus` show `empty` verbatim. `cmdResult` on an
`empty` job prints "Antigravity finished without producing any output" plus the
log path and the conversation id — not a blank success, and not a fabricated error.

**Pruning (E).** New `pruneJobs(env)` in `jobs.mjs`:

- Runs once at the end of every `createJob`, wrapped in try/catch — pruning must
  never fail a run.
- Deletes a job directory when it is **older than `ANTIGRAVITY_CC_JOB_TTL_DAYS`
  (default 14)** by `startedAt`, **or** when it falls outside the newest
  `ANTIGRAVITY_CC_MAX_JOBS` (default 50) by `startedAt`.
- **Never deletes a job whose status is `running`, or whose pid is alive**,
  regardless of age. A long-running background job must survive its own TTL.
- Prunes across all repositories, not just the current `cwd` — the cap is on the
  store, not per-repo.
- Deletion is `rmSync(dir, {recursive:true, force:true})` on the job directory
  only, resolved under `jobsRoot()`. A job id that does not match
  `/^agy-[a-z0-9]+-[a-z0-9]+$/` is skipped, never deleted — the id reaches this
  path from user input via `readJob(id)`.

### 4.8 `setup` (improvements D, and B3)

- Version floor **`1.1.20`**, as `MIN_RECOMMENDED_AGY` in `capabilities.mjs`.
  Chosen because 1.1.20 fixed print mode reporting benign tool errors as fatal
  exit codes, and 1.1.18 fixed print mode exiting 0 with an empty response on a
  dropped stream — the two upstream fixes that change how reliably this plugin can
  report an outcome. JSON support is **not** version-gated; it is probed by the
  §4.3 fallback.
- `parseVersion("1.1.21") → {major:1, minor:1, patch:21}`. Tolerates a leading
  `v` and trailing build metadata. Returns `null` on anything unparseable —
  including the fake binary's `9.9.9-fake`, which must parse cleanly as
  `{9,9,9}`, so parse the leading `\d+\.\d+\.\d+` and ignore the remainder.
- `compareVersions(a, b) → -1|0|1`. A `null` version yields "unknown" and
  produces **no** warning — never nag a user whose binary we cannot identify.
- Below the floor: setup adds a next-step line —
  ``Your `agy` is <v>; 1.1.20+ is recommended. Update with `agy update`.`` —
  and stays `ready` (advisory, not blocking). `setup --json` gains
  `versionOk: true|false|null`.
- Auth heuristic accepts `.db` **or** `.pb` conversation files (B3).

### 4.10 Usage reporting (falls out of A)

When `RunResult.usage` is present, `renderResponse` appends one line below the
resume footer, outside the untrusted fence:

```
Antigravity: 14,550 tokens · 1 turn · 2.1s
```

Omitted entirely when usage is absent (legacy path). Never inside the fence — it
is companion-generated text and must not sit in the region labelled untrusted.

## 5. Test requirements

Existing tests must keep passing unchanged except where this spec changes observable
behaviour. Current baseline: **41 passing**.

**`tests/fake-agy.mjs`** gains modes, selected by `FAKE_AGY_MODE`. The fake must
honour `--output-format json` (emit JSON) and ignore it otherwise (emit text), so
one mode exercises both paths:

| Mode | Behaviour |
| --- | --- |
| `success` *(existing)* | unchanged text response; now also emits the JSON shape when `--output-format json` is present |
| `json-error` | `status:"ERROR"`, `error:"RESOURCE_EXHAUSTED (code 429): Individual quota reached. … Resets in 152h59m39s."`, exit 0 |
| `json-empty` | `status:"SUCCESS"`, `response:""`, exit 0 |
| `json-auth` | `status:"ERROR"`, `error:"error getting token source: You are not logged into Antigravity."`, exit 0 |
| `legacy-flag-error` | exits 2 with stderr `flag provided but not defined: -output-format`; on the retry (no `--output-format`) behaves as `success` |
| `noisy-log-success` | text success **and** a log containing the 1.1.21 wrapper prefix plus `You are not logged into Antigravity.` startup lines |
| `wrapped-quota` | empty stdout, log with the 1.1.21 `ERROR: logging before google.Init: E0827 …` wrapper around a `RESOURCE_EXHAUSTED` line |

**Required cases:**

- **T-R1** `parseAgyJson` returns `null` for plain text and never throws.
- **T-R2** `parseAgyJson` recovers the JSON object when it is preceded by noise lines.
- **T-R3** `fromJson` maps `SUCCESS` + non-empty response → `outcome:"success"` with camelCased usage.
- **T-R4** `fromJson` maps `SUCCESS` + empty response → `outcome:"empty"`, `error:null`.
- **T-R5** `fromJson` maps `ERROR` + a quota `error` string → `outcome:"failed"`, `kind:"quota"`, `resetsIn:"152h59m39s"`.
- **T-R6** `fromJson` normalises `conversation_id:""` → `null`.
- **T-R7** `classifyRun` with `timedOut:true` returns `kind:"timeout"` even when stdout holds a valid SUCCESS JSON blob.
- **T-R8** `classifyRun` falls back to `fromLegacy` for non-JSON stdout and recovers the conversation id from the log.
- **T-L1** `unwrapLogLine` strips the 1.1.21 wrapper **and** the glog stamp, and is still a no-op on plain text.
- **T-L2** `scanAgyLog` classifies auth from a real 1.1.21 signed-out log — the exact fixture that returns `error:null` today. *This is the B1 regression test.*
- **T-L3** `scanAgyLog` classifies quota from a wrapper-prefixed line, and the rendered message contains no `logging before google.Init` noise. *This is the B2 regression test.*
- **T-L4** End-to-end, `noisy-log-success`: stdout is a normal response and contains no auth error. *This is the §4.6 false-positive guard.*
- **T-A1** `buildPrintArgs` emits `--output-format json` and `--disable-slash-commands` by default, and `-p <prompt>` remains the final pair.
- **T-A2** `buildPrintArgs` emits `--model` / `--effort` / `--mode` only when given.
- **T-A3** End-to-end `legacy-flag-error`: the companion retries without the JSON flags and returns the response; the downgrade note is on stderr, and stdout contains no diagnostic text.
- **T-A4** `--effort bogus` exits without spawning `agy` and names `low|medium|high`. Assert non-spawn by pointing `ANTIGRAVITY_CC_AGY_BIN` at a fake that writes a sentinel file.
- **T-A5** `--plan` produces both `--mode plan` and `--sandbox`.
- **T-A6** `--model gemini-3.1-pro-high` reaches the argv and produces **no** stderr warning. *This is the B4 regression test.*

## 6. Acceptance criteria

1. `npm test` passes, with every case in §5 present.
2. On a signed-out `agy` 1.1.x, `/antigravity:delegate` reports "not authenticated"
   with sign-in guidance — verified against a real signed-out log fixture, and
   manually if an account is available.
3. On a signed-in `agy` 1.1.x, a foreground delegate returns the response, the
   conversation id, and a usage line.
4. `/antigravity:delegate --model gemini-3.1-pro-high --effort high <task>` runs on
   that model with no warning on stderr.
5. `/antigravity:delegate --model no-such-model <task>` surfaces `agy`'s own
   model-list error to the user rather than an empty result.
6. A background job that fails reports `failed`; one that returns nothing reports
   `empty`; neither reports `done`.
7. `/antigravity:setup` reports the version, and advises `agy update` below 1.1.20.
8. After 60 delegates, `~/.antigravity-cc/jobs` holds at most 50 job directories
   plus any still running.
9. Every `--output-format json`, `--model`, `--effort`, `--mode`, and
   `--disable-slash-commands` claim in the docs is reproducible by running the
   command the doc shows.
10. `grep -rn "Gemini 3" plugins README.md CONTRIBUTING.md package.json` returns
    nothing.

## 7. Risks

| Risk | Mitigation |
| --- | --- |
| The new auth patterns fire on a successful run's startup noise. | Log is consulted only when there is no response text; enforced by T-L4. |
| JSON stdout mixes with log noise on the same stream. | `parseAgyJson` two-stage parse (§4.2); falls back to legacy rather than throwing. |
| `--output-format json` changes shape in a future `agy`. | `fromJson` reads only `status`, `response`, `conversation_id`, `error`, `usage`, `duration_seconds`, `num_turns`, and tolerates every one of them missing. An unrecognised shape falls back to `fromLegacy`. |
| The one-shot flag-rejection retry masks a real failure. | Retry is gated on a flag-parse stderr pattern **and** empty stdout, runs once, and logs the downgrade to stderr. |
| Pruning deletes a job the user still wanted. | TTL 14 days and 50 jobs are generous; running jobs are exempt; both are env-overridable; only well-formed job ids under `jobsRoot()` are eligible. |
| `--disable-slash-commands` breaks a user relying on `agy` slash commands in a delegated prompt. | No known use; the companion never emits one. Documented in the reference doc's unused-surface list. |
| Upstream `agy` moves again in three months. | T-D1 catches naming drift; the reference doc carries the verified-against version in its header; `setup`'s floor makes the dependency explicit. |

## 8. Out of scope, worth revisiting

- `--json-schema` could make `review` return structured findings instead of prose,
  which would let the plugin render severity-sorted findings and feed
  `ReportFindings`-shaped output. Larger change; separate spec.
- `--input-format stream-json` would allow multi-turn delegation without
  re-spawning `agy` per turn.
- `agy mcp` means the plugin could expose the user's MCP servers to delegated
  runs. Needs a security review of its own before it goes anywhere near a
  write-capable agent.
